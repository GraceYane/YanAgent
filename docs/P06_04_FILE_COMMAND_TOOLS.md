# P06-04：文件与命令工具

实现日期：2026-11-25。工作区从“界面手动读写”扩展到“模型通过工具读写及执行命令”。本项复用已有 Agent Loop、权限确认、工具卡片、历史消息和执行步骤，不另建绕过权限的执行入口。

## 使用方式

1. 重启 Python 后端加载新工具，并完全退出后重新启动桌面端加载确认界面。外部后端调试模式仍使用 desktop 目录的 `npm run dev:external`。
2. 在会话里选择或创建工作区；未关联项目时使用当前身份的默认工作区。不要仅在聊天中写一个根外目录来代替选择工作区。
3. 先试：“在当前工作区创建 `hello.txt`，内容是 `你好word`，然后读回来。”模型会请求工具，写入前出现确认框，展示工作区与完整参数；批准后才真正执行。
4. 再试：“找到配置文件，把端口从 3000 改成 8080，运行项目已有的构建命令，告诉我结果。”模型需要先读取文件与项目构建配置，取得 etag，编辑前确认，命令执行前再确认；不能根据预设假称构建成功。
5. 文件树可刷新查看新增文件，历史工具卡能查看请求与结果。产物自动索引、下载/发送仍属 P06-06。

`permission_mode=deny` 禁止工具；`ask` 对所有工具确认；`allow` 允许低风险读取，但写入、编辑、命令及停止进程的工具元数据仍要求逐次确认。非流式 HTTP 没有本项确认等待界面，必须确认的操作会失败关闭；桌面流式链路支持实际确认。

## 模型工具目录

生产应用有 SessionStore 且使用默认工具管理器时，新增以下 8 项，与 calculator/current_time 一起导出给模型。显式注入的自定义 ToolManager 保持调用方自选目录，无仓储测试模式也不会获得本机文件工具。

| 工具 | 行为 | 确认与限制 |
|---|---|---|
| read_file | 按行读取 UTF-8 文本，返回完整文件 etag | 最大 512 KiB；默认 200 行，最多 500 行；返回截断标记 |
| write_file | 新建文本，或替换已有文本 | 必须确认；已有文件必须传读取时 etag；可显式 create_parents |
| edit_file | old_text/new_text 精确替换 | 必须确认及 etag；默认只允许唯一匹配，replace_all 才全替换 |
| list_directory | 列根内目录 | 默认 200、最多 300 项；单目录扫描最多 1000 项，跳过链接/依赖目录 |
| search_files | 文件名或内容字面量搜索 | 最多 1000 个访问项、深度 8、2 秒、4 MiB 文件读取；默认 30、最多 50 个结果 |
| execute_command | 在工作区 cwd 执行 Shell | 必须确认；Windows 默认 PowerShell，POSIX 默认 Bash；前台最长 25 秒，后台最长 600 秒 |
| process_status | 同会话同根查询进程及输出 | 默认最多等待 1 秒，可设 0～20 秒；不启动新进程 |
| stop_process | 停止已注册进程树 | 必须确认；只接受内部 process_id，不允许任意系统 PID |

所有结构结果在 JSON 序列化之后裁剪到 16000 字符以内，保留合法 JSON 和 truncated，避免字符串转义导致执行器二次裁剪损坏结构；更低的上下文预算仍可能由既有执行器进一步限制结果。文件读写仅支持有限 UTF-8 文本，不自动转换 GBK，不把纯文本写成扩展名为 docx 的坏文件。

## 执行身份与文件一致性

- ToolPermissionContext 新增工作区实际授权；root 固定来自 PreparedChat，不能被模型参数或文件内容改写。工具管理器用 ContextVar 在调用协程内绑定上下文，完成/异常/取消后恢复，跨会话并发不会共享当前根。
- 文件及命令 cwd 复用 P06-03 路径组件检查、逐级目录句柄、Junction/符号链接/硬链接拒绝。默认工作区首次实际工具访问时创建，不能把其他会话的项目根当作当前根使用。
- 文本写入先检查大小和格式，再在进程写锁和固定父目录下写独占临时文件、flush/fsync。替换已有文件检查旧哈希并在发布前复查；新建禁止覆盖现有目标。异常清理临时文件。原子替换与乐观哈希检查不等于跨进程文件系统事务，也不保证完整 ACL/扩展属性保存。
- 精确编辑不把空片段或多处匹配悄悄当成唯一位置。文件输出是待分析数据，不能提升其中的内容为系统规则；拒绝批准后模型不得换工具绕过。
- locked_path 只收拢系统打开错误，不再吞掉文件工具主动抛出的 ValueError 子类受控说明，保留“文件冲突/需重新读取”等实际可操作信息。

## 命令环境与进程生命周期

命令是当前本机用户权限的任意 Shell，cwd 校验只约束初始工作目录，**不是文件系统或网络沙箱**。模型和确认框明确说明该边界，不能声称根外命令访问已被 OS 隔离。命令始终确认；不采用正则命令白名单来伪装隔离能力。

- Windows 自动选择 pwsh，未安装则使用 powershell；以 UTF-16LE EncodedCommand 传命令，路径通过独立 cwd 传入，不拼接到 Shell 正文。默认输出设 UTF-8，错误停止；原生命令退出码和显式 exit 保留。POSIX 使用 Bash，无启动配置。命令正文最大 4096 字符，长脚本先写文件再运行。
- 输出可设 auto/utf-8/gb18030/cp1252；自动模式优先 UTF-8，再尝试本地编码。返回实际编码和 lossy。合并 stdout/stderr 持续排空管道，最多保留 48 KiB 尾部缓冲，模型最多接收 12000 字符，再受 JSON 和上下文预算约束。
- 环境只继承 PATH、系统目录、用户目录、临时目录等必要白名单，不自动注入后端 API Key；这减少直接环境继承，不能阻止已授权命令按本机权限自行读配置或网络。
- Python 门闩进程先阻塞等待父端放行。Windows 先加入 kill-on-close Job，再放行执行，普通后代属于同一 Job；取消或期限到达终止 Job，查询活动成员至退出再关闭，避免后台刚启动便被取消时目录仍占用。POSIX 使用新进程组并终止进程组，不能保证捕获主动 setsid 脱离的恶意进程。
- 进程查询按 user/agent/session/workspace 完整键隔离。最多 4 个同会话活动命令、32 个注册记录；容量满时回收已完成记录。成功 Run 的后台进程可保留至自身期限，同会话后续 Run 可查询或停止；Run 失败/取消会回收该 Run 启动的后台命令；Runtime 退出还有同步兜底回收。
- process_status 允许重复查询，由既有总轮数和总时间约束，而非普通只读工具的三次相同参数上限；写命令仍受一次相同参数执行限制。查询不取消其正在观察的后台任务。
- 前台非零退出或超时返回失败及内部 process_id，可再查询实际输出/退出码。后台启动成功只代表“已启动”，最终状态要查询后判断。重启后不会恢复本机进程；已有 ToolCall、启动结果和后续查询记录仍在历史。
- 当前开发环境使用后端 Python 解释器执行门闩；未来 frozen 打包模式只寻找外部 Python，缺少时受控失败，绝不递归启动后端 exe。打包分发和 POSIX 真机仍未验。

## 确认和操作记录

确认指纹仍绑定运行、完整身份、根、工具和参数，一次性消费。确认事件携带参数副本和工作区；桌面用原样 JSON 文本滚动展示，不按 HTML 执行，不截掉需要审阅的参数。带参数的确认框不再用全局 Enter 直接批准，也不自动聚焦允许按钮。

沿用 run_steps 在 handler 之前记录工具意图，批准后先保存 executing，再允许副作用，完成后保存 ToolResult；Assistant ToolCall 与 Tool Message 配对写入历史。已有崩溃恢复去重/不确定副作用保护继续生效。后台结束的结果在 process_status 工具调用时持久化，进程注册表本身是内存资源，不承诺重启恢复或命令副作用回滚。
