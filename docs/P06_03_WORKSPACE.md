# P06-03：工作区与会话项目关联

完成日期：2026-11-25。本项接通桌面的项目选择器、文件树、文本查看和手动编辑，不注册模型文件/命令工具；Agent 主动读写文件属于 P06-04。

## 如何使用

1. **重新启动后端和桌面端**。本项修改了 Electron 主进程和 preload，仅刷新页面或重启 Python 不会更新桌面凭证接口。外部调试模式继续使用既有 `npm run dev:external` 构建并启动桌面。
2. 在聊天输入框下方点击文件夹图标，选择「打开项目」并使用系统目录选择框挑选本机实际目录；或者「新建项目」，在 YanAgent 托管项目目录中新建一个空目录。
3. 右侧「文件」面板显示所选目录，支持逐级进入、按文件名查找、文本预览。选中文本文件后点击编辑，保存会回写实际文件。
4. 不同会话可以关联不同目录，重启后保留；恢复默认工作区只改变当前会话，不删除原目录。项目管理改名仅改变显示名，移除只忘记记录并解除当前身份的关联，均不删除磁盘内容。
5. 任务排队或运行中不允许切换项目或移除其关联。任务准备时固定 workspace_root，并在 Run 与可信模型上下文中记录；工作区路径不被解释为指令，也不等于模型已经读取文件。

当前仍只有 calculator/current_time 模型工具。手动编辑是用户在桌面发起的操作，不通过模型工具权限模式；后续模型文件操作需要独立接入 ToolManager、权限确认与执行记录，不能因为设置了工作区就直接授予自动读写能力。

## 目录与持久化

默认数据目录继续为 `~/.yanagent` 或显式 YAN_DATA_DIR，不复用 CowAgent 数据。默认工作区和托管项目分别是：

```text
<YanAgent 数据目录>/workspaces/<用户和 Agent 的作用域哈希>/default
<YanAgent 数据目录>/workspaces/<用户和 Agent 的作用域哈希>/projects/<项目名>
```

托管目录按需创建，不在普通聊天准备时批量创建。新项目名只允许单个普通目录名，不接受路径；已有目录不会覆盖。创建后如果关联失败，只尝试回收本次新建的空目录，不递归删除已有或外部写入的内容。

Schema v4 新增 workspace_projects，按 user_id、agent_id、规范路径保存项目显示名、最近使用和排序。每个身份最多登记 200 个项目。会话绑定在 metadata.workspace_project 下，与 model_settings、摘要和上下文位置事务合并，不互相覆盖。已有 v1～v3 通过新增迁移前向升级，旧迁移不改写；项目列表和会话归属均使用完整身份查询。

会话列表附加 project 信息，多项目/默认空间并存时按项目分组。项目排序持久化；当前默认分组固定在最前，尚未单独持久化默认分组的任意拖动位置。

## 路径策略

- 接受本机绝对项目目录；默认和相对文件路径均解析到当前会话根。绝对文件路径也必须在该根内，不能通过“绝对路径”绕过边界。
- 按路径组件比较归属，拒绝 `..`、控制字符、同前缀兄弟目录越界。Windows 额外拒绝 UNC、设备前缀、盘符相对路径、ADS、保留设备名及尾部点/空格歧义。
- **拒绝全部符号链接和 Windows 重解析点，包括 Junction，即使目标仍在根内**。项目根及其各级祖先也检查；OneDrive 占位等重解析文件可能因此不可用，应选择实际普通目录。本项没有实现允许内部链接的白名单。
- 普通文件硬链接计数不为 1 时拒绝读写，避免根内别名直接写到根外对象；不支持设备、管道或其他特殊文件。
- Windows 逐级用 OPEN_REPARSE_POINT 打开目录，并在操作期间不共享删除；读取前核验句柄属性与最终路径，阻止目录改名/链接替换的常见穿越。POSIX 使用逐级 dir_fd、O_NOFOLLOW 与普通文件检查。读写路径不能只做一次 realpath 字符串判断后盲目打开。

这属于应用文件服务的访问控制，不是 OS/容器沙箱。不能阻止具有相同操作系统权限的其他程序直接修改文件，也不声称解决跨进程的恶意竞态、所有挂载/驱动或网络文件系统问题。

## 文本、编辑与并发

- 单次读取/保存上限 512 KiB；截断、非 UTF-8 有损解码、包含 NUL 的内容不可编辑。没有自动猜测 GBK 或覆盖无法无损读取的文件。
- 文本预览对截断或编码替换明确显示提示；本阶段不提供原文件下载入口，避免把有限预览或二进制解码结果当作原文件下载。
- 文件树最多 500 项，跳过 .git、.venv、node_modules、__pycache__ 和不可访问链接。文件名搜索最多访问 3000 项、深度 8、约 2 秒、返回最多 100 项；这些是有限查找，不保证搜索所有大项目内容。
- mtime 以整数毫秒传递，避免 JavaScript 无法精确表示纳秒整数。编辑另携带 SHA-256 ETag，外部修改即使时间戳相同也能检测。
- 保存前检查基线版本；同进程不同服务共享写锁，写入同目录独占临时文件、flush/fsync，提交前再次核对当前内容，最后原子替换。失败保留原文件并回收本次临时文件；POSIX 保留普通权限位。没有承诺完整 ACL/扩展属性保留或断电下目录项完全持久化。
- 冲突返回既有界面识别的 `status=error, code=conflict`，用户可以重载或明确确认覆盖。强制覆盖仍不能绕过路径、链接、编码和大小限制。外部程序最后检查后的并发变化仍属于乐观并发控制边界，不是跨系统事务。
- 文本/代码/HTML 均作为文本读取，HTML 不在后端作为页面执行。其他二进制预览、下载原文件与多媒体能力不属于本项。

## 本地文件接口的访问凭证

普通聊天旧接口的 CORS 行为不被当作读盘授权。新增文件/项目 JSON 接口必须携带本次后端进程随机生成的 X-YanAgent-Workspace 凭证。

桌面 renderer 只能经 preload 请求主进程取得凭证。主进程确认发送者是主窗口，且 API 地址对应当前本机后端端口，才用 Node fetch 调用 `/api/workspace/access`；后端拒绝带 Origin（包括 null）或浏览器 Sec-Fetch-Site 的凭证获取请求。凭证不放配置文件、日志或普通文件预览 URL。主进程和文件请求拒绝重定向，避免把本机凭证带向其他服务。

预览地址使用独立的单文件 HMAC 凭证，绑定身份、会话、根目录、相对路径和一小时有效期。预览验证与读取在同一个会话关联锁内执行，改路径、换项目、过期或后端重启后旧链接失效。响应为 text/plain，并设置 nosniff、sandbox CSP、no-referrer、no-store，不执行源文件脚本。

这是桌面本机模式的接入；普通浏览器没有 preload，因此本项未开放完整 Web 文件管理。拥有本机同用户进程权限的工具仍可作为可信本地客户端访问，不能把此凭证机制写成用户账户鉴权或操作系统隔离。

## HTTP 与界面联调

沿用复制界面的实际接口：

| 接口 | 行为 |
|---|---|
| GET /api/projects | 当前会话项目、默认目录、最近项目 |
| POST /api/projects/select | 选择已有目录或恢复默认 |
| POST /api/projects/create | 托管目录中新建并关联 |
| POST /api/projects/order | 项目记录排序 |
| PUT/DELETE /api/projects/manage | 改显示名/忘记项目，不删除内容 |
| GET /api/workspace/tree、search、resolve | 有限文件树、文件名搜索和单项定位 |
| GET /api/workspace/read | 有限文本、可编辑状态、mtime 与 ETag |
| POST /api/workspace/write | 用户手动保存已有文本 |
| GET /api/workspace/preview | 持单文件短期凭证读取文本 |

未知字段与非默认 Agent HTTP 请求拒绝，不允许 UI 任意传 user_id 切换身份。选择器显示变更失败；树和编辑器防止较早的异步结果覆盖新会话/新项目的同名文件。模型只获得根路径和“尚未读取文件”的可信说明，不自动注入项目正文。

### 2026-11-25 桌面联调修正

实际桌面根目录请求为 `/api/workspace/tree?path=&session=...`，空 path 表示当前根。初版复用的严格查询解析器错误拒绝空值，导致 400；现仅对工作区 path/session 显式允许空值，其他参数与重复参数仍严格校验。补入实际 URL、新建项目 POST 和默认 session 的回归。

工作区凭证缺失/失效使用独立的 workspace_access_denied，预览链接失效为 workspace_preview_expired，不再复用模型供应商权限错误。旧 preload 未加载工作区接口时，桌面在发请求前明确提示完全重启；不能通过省略凭证继续请求。当前验证更新为工作区 24 项、全量 299 项通过，桌面完整构建通过。用户原有窗口未由本次工具强制关闭，需要重新启动后加载修复。
