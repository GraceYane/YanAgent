### 3.1 小米（XM）

职位描述

1. 面向产品场景设计与实现 AI Agent 能力，覆盖任务接入、上下文管理、执行编排、结果回写等完整链路。
2. 基于开源或自研，建设并迭代多 Agent 编排框架，支持本地 daemon 与云端两种 runtime，参考 OpenClaw 等项目在 Gateway、Sessions、Skills、Sandbox 上的设计思路。
3. 设计、开发与维护 MCP Server / Client 及相关 Tooling，完成内部系统（数据、监控、CI、知识库等）与 Agent 的信息打通。
4. 参与 Skills / Hook / Sub-agent 设计与实现，沉淀可复用的能力组件、Prompt 模板与验证回路（verification loop）。
5. 推动 Claude Code / Codex / Cursor 等 Coding Agent 在团队内常态化使用，沉淀规范、脚手架与最佳实践。
6. 与产品、业务、数据、安全协作，确保 Agent 方案在可用性、合规性、稳定性、可观测性上达标。
7. 持续优化 Agent 链路在性能、稳定性、Token 成本与可维护性上的表现。

要求

1. 计算机相关专业本科及以上，能保证每周 4 天及以上的实习时长（具体时长可面议）。
2. 熟练掌握 Python，并另外熟悉至少一种编程语言（Go / Java / TypeScript / Scala）。
3. 深度使用过 Claude Code / Codex / Cursor 中的至少一个，能清晰讲述自己在 Prompt 编排、上下文管理、子 Agent 委派、Verification Loop 上的实践与踩坑。
4. 拆解过至少一个开源 Agent 项目的内部机制，例如：OpenClaw 的 Gateway、多 Agent 路由、Skills、Sandbox 模型；Claude Agent SDK / Claude Code 的工具调用与上下文协议；MCP (Model Context Protocol) 的 Server / Client 实现；任意多 Agent 编排框架的 Hook、Skill、子 Agent 触发机制。
5. 写过至少一个可运行的 Agent 类 Side Project：自定义 Agent、MCP Server、Skill、Prompt 框架、Agent Benchmark 均可。
6. 中文沟通顺畅，能写清晰的方案、设计文档与复盘。

## 5. 有关联但不能直接等同的岗位能力

| 岗位内容 | 当前计划能提供的基础 | 尚不能据此声称完成的内容 |
|---|---|---|
| XM 本地 daemon 与云端两种 runtime、Gateway | Bridge、桌面后端和 Web/渠道路由 | Electron 启动子进程不等于独立 daemon；本地 HTTP 服务不等于云端部署、多租户运行时或完整 Gateway |
| XM Sandbox、WX 沙箱隔离编译 | 工具权限、工作区路径和命令访问控制 | 权限校验不等于容器/操作系统沙箱，更不等于小程序端的隔离编译 |
| XM MCP Server / Client、内部 CI/监控接入 | P08 实现 MCP Client，测试 Server 可用于协议验证 | 测试桩不等于独立交付的业务 MCP Server；目前没有真实企业内部系统接入 |
| XM Hook | Runtime 事件与工具生命周期 | 能推送事件不等于存在可注册、按序触发、失败可隔离的 Hook 机制 |
| XM Verification Loop、DYQ 结果汇总验证 | 失败反馈、测试和效果评测 | 重试或普通工具循环不等于“验证→结构化失败→修复→再次验证”的闭环 |
| DYG / DYQ / TX Planning、任务分解 | P04 工具决策、P10 子任务委派 | 委派本身不证明有显式任务计划、依赖图、完成条件、重规划或规划效果评测 |
| TX Reflection | 工具错误反馈和执行结果记录 | 将错误返回模型不等于有明确的反思/批判策略，也不证明反思能提升效果 |
| DYQ 需求理解、测试生成、代码评审、缺陷发现 | 通用 Runtime、工具、Skills、Sub-agent | 通用能力不等于已实现质量场景工作流；业务价值需有真实任务与评测证据 |
| TX LangGraph / AutoGen / CrewAI / MetaGPT 实践 | 自研 Runtime 和 CowAgent 源码拆解 | 实现 YanAgent 不能自动写成使用过这些框架；另需实际搭建或明确的学习实践证据 |
| XM 团队 Coding Agent 推广、DYG AI IDE 实践 | 使用 Coding Agent 辅助开发、规范与过程记录 | 个人开发不等于团队推广；需记录实际人工决策、工具使用、踩坑及验证，才可描述个人实践 |
| WX Text-to-Skill | Skill 描述、模型代码生成和工具执行基础 | CowAgent 的流程型 SKILL.md 不等于标准化小程序 JSON/JS 组件编译、动态下发或原生 API 对齐 |
| WX CPT / SFT / RL、C/C++ | 当前 Python/TypeScript 应用开发 | 应用编排不等于模型训练、强化学习或 C/C++ 工程经历 |

以上差距作为求职参考保留，不自动加入 P01～P12 的完成条件。若参考源码盘点发现已有对应机制，则按原复现范围记录；如确需新增专项，在获得用户明确需求后单独编号、设计和排期。

## 6. 后续开发的详细记录格式

每次完成需求先写原有的“需求、完成内容、涉及文件、验证结果、后续事项”。有岗位重合时，在同一条 `workProcess.md` 记录追加下列部分：

```markdown
### 岗位要求关联与实践证据

- 开发任务：Pxx-xx，任务名称。
- 对应条款：岗位编号和条款编号，引用具体能力要求。
- 重合范围：本次实现了条款中的哪一部分，还有哪些未覆盖。
- 具体实现：代码文件、关键类/方法、消息流或状态流。
- 设计原因：解决的问题、依赖和方案取舍，参考 CowAgent 的对应机制。
- 验证证据：测试命令/用例/报告、实际运行轨迹；明确模拟或真实验证。
- 难点与踩坑：实际遇到的问题、原因、修复方式和验证结果；未遇到则如实说明。
- 指标与结论：测量条件、结果、限制；没有测量不写提升百分比。
- 可用于面试讲述的事实：用已完成且能复现的内容概括，不提前生成虚构经历。
- 后续差距：未实现、未联调或需要独立研究的部分。
```

只有文档或规范变更时，记录对应的文档表达与工程规范实践即可，不将本次岗位归档写成 Agent 技术实现。
