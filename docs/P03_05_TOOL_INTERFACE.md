# P03-05 工具列表接口与阶段验收

状态：已完成
完成日期：2026-10-28
后续状态：P04-01 已完成；下一项为 P04-02 非流式 Agent Loop

## 1. 本阶段交付

P03-05 将 P03-01～P03-04 的注册、执行和权限能力接入应用级工具目录，并替换桌面后端原有的空占位接口：

```text
YanAgentApplication 启动
          ↓
创建 ToolManager
          ↓
注册 calculator / current_time
          ↓
GET /api/tools
          ↓
桌面能力页显示真实工具名称和说明
```

`YanAgentApplication` 默认拥有一个进程级 `ToolManager`，并注册 P03-02 的两个安全示例工具。测试和未来不同 Agent 也可以显式注入独立注册表；显式注入空注册表时不会被默认工具静默覆盖。

## 2. HTTP 契约

桌面现有客户端调用：

```http
GET /api/tools
```

当前响应形状：

```json
{
  "status": "success",
  "tools": [
    {"name": "calculator", "description": "..."},
    {"name": "current_time", "description": "..."}
  ]
}
```

列表按工具名称稳定排序，每次返回独立快照。桌面接口只暴露 `name + description`，不暴露 Python handler、参数 Schema、确认 ID、内部风险或权限上下文，也不会返回配置和密钥。

该接口是“已注册工具目录”，不是执行授权结果。工具出现在页面中不代表当前调用一定能运行；真实执行仍必须经过 P03-03 参数校验和 P03-04 的模式、作用域、风险与确认判断。

## 3. P03 综合验收

P03-05 新增一组跨层验收，覆盖需求文档列出的关键路径：

| 验收项 | 验证行为 |
|---|---|
| 工具列表 | 真实回环 HTTP 返回计算器和时间工具，不再是空数组。 |
| 重复注册 | 同名定义抛出 `ToolAlreadyRegisteredError`，原定义不被覆盖。 |
| 非法参数 | 缺少必填字段返回关联调用 ID 的失败 `ToolResult`，handler 执行次数为 0。 |
| 权限拒绝 | `deny` 在 handler 前失败，执行次数保持 0。 |
| 正常执行 | 计算 `(2 + 3) * 4` 返回 `20`，结果关联 `calculator-1`。 |
| 超时 | 慢 handler 返回结构化“工具执行超时”，进程继续服务。 |
| 执行失败 | 未知异常正文不公开，下一次调用仍可返回 `recovered`。 |

参数、权限、超时和失败的专项矩阵仍保留在 P03-03/P03-04 测试中；P03-05 的综合测试用于证明这些能力通过同一个 `ToolManager` 入口可以协同工作，而不是互相独立的占位实现。

## 5. P03 阶段结论与边界

P03 至此完成：工具可以统一定义、注册、发现、校验、授权和执行，并能通过桌面 HTTP 接口查看目录。当前仍有明确边界：

- `/api/tools` 只列目录，不允许从 HTTP 任意提交工具调用，避免在 P04 身份、历史和循环尚未接好时形成旁路执行接口。
- 桌面确认 UI 尚未实现；需要确认的工具继续默认拒绝。
- 模型 Schema 尚未注入真实聊天，模型不会自动调用计算器或时间工具。
- Assistant 工具调用消息、Tool Result 和下一轮模型请求的完整循环属于 P04。
- 文件、命令、网页等完整工具及资源级权限属于 P06；当前 scope 不是 OS Sandbox。
