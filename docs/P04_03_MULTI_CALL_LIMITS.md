# P04-03 多调用与限制

状态：已完成  
完成日期：2026-11-03  
下一项：P04-04 流式循环

## 1. 本阶段解决的问题

P04-02 已能完成非流式 `模型 → 单个工具 → 模型`，但同一模型响应包含多个 ToolCall 时会整体拒绝，而且模型持续请求工具时没有运行边界。P04-03 将普通非流式循环扩展为：

```text
模型返回一组 ToolCall（保持原顺序）
                 ↓
先保存携带整组调用的 Assistant Message
                 ↓
依次执行 ToolCall 1、2、3……
                 ↓
每次保存相同 tool_call_id 的 Tool Result
                 ↓
整组结果补齐后再次请求模型
```

工具仍然只在 YanAgent 本地执行，Provider 只负责返回调用意图。即使工具定义声明 `parallel_safe=True`，本阶段也按需求顺序执行，不提前引入并行竞态。

## 2. 同轮多工具的消息完整性

`AgentLoop` 先验证并保存包含全部 ToolCall 的 Assistant Message，再按模型给出的列表顺序调用 `ToolManager.execute()`。每个结果都带原调用 ID，并按执行顺序写入数据库和下一轮模型上下文。

当连续失败或总超时在一组调用中间触发时，后续工具不再产生真实副作用，但循环会为剩余调用写入明确的失败 Tool Result。这样一组 Assistant ToolCall 不会因为限制触发而遗留无法配对的调用，后续完整历史仍满足 `validate_conversation()`。

## 3. 默认限制与终态

| 限制 | 默认值 | 行为 | 稳定错误码 |
|---|---:|---|---|
| 最大模型轮数 | 20 | 最后允许轮次可以直接返回最终文本；若仍请求工具，在保存或执行该轮工具前停止 | `agent_loop_max_turns` |
| Agent Loop 总超时 | 600 秒 | 剩余预算同时限制模型和工具等待；工具阶段超时会补齐本组失败结果后停止 | `agent_loop_timeout` |
| 单工具超时 | 30 秒 | 继续由 `ToolManager` 取消 handler，并返回 `ToolResult(is_error=True)` | 作为工具失败回写模型 |
| 连续工具失败 | 3 次 | 任一成功结果将计数清零；达到上限后跳过本组剩余真实执行、补齐失败结果并停止 | `agent_loop_consecutive_tool_failures` |

三个循环限制都可以通过 `AgentLoop` 构造参数覆盖，测试可使用很小的阈值验证边界；当前桌面配置页仍展示既有的 20 步设置，运行时配置入口留待后续统一收口。

限制错误继承统一 `AgentError`。普通聊天层沿用现有 Run 生命周期，把它们转换为唯一一次 `failed` 终态；外部取消仍保持 `cancelled`，不会被误报成总超时。空白文本且没有 ToolCall 的模型响应现在明确使用 `empty_model_response` 失败，不再保存空的最终 Assistant。

## 4. 总超时与工具超时的区别

- 总超时约束整次 Agent Loop，包括多轮模型等待和工具等待。
- 单工具超时只约束一次 handler，由 `ToolManager` 负责；它产生结构化失败结果，模型原本仍有机会解释或改用其他工具。
- 如果单工具失败使连续失败次数达到上限，循环再以连续失败错误结束。
- 如果 Agent 剩余总预算先耗尽，当前工具被取消，当前和同组剩余调用获得总超时失败结果，随后 Run 失败。

数据库追加和最终消息保存仍保持既有事务语义。P05 会进一步处理 Bridge 级取消、重试、并发与崩溃恢复，不在本阶段引入自动重试已执行工具。

## 5. 验证

`tests/test_agent_loop.py` 现有 12 项测试覆盖：

1. 两个模型轮次各调用一个工具后生成最终答案；
2. 同一模型响应中的两个计算器调用按顺序执行并保存为 `Assistant → Tool → Tool`；
3. 未知工具、参数错误和权限拒绝作为 Tool Result 回写；
4. 20 轮边界可覆盖为小阈值，最后允许轮次的工具不会产生无法消费的副作用；
5. 连续失败达到三次后 Run 进入稳定失败终态；
6. 同轮达到失败上限时跳过剩余真实执行并补齐调用 ID；
7. 慢模型触发整次循环总超时；
8. 多工具组中工具耗尽总预算时取消当前工具、跳过后续副作用并补齐结果；
9. 单工具超时取消 handler，并纳入连续失败计数；
10. 空模型回复、模型异常和正常无工具回答保持各自终态。

全量 206 项自动化测试通过；另通过 Python 编译检查和 `git diff --check`。真实 DeepSeek 多工具响应具有模型侧不确定性，本阶段以 Fake Provider 和真实 ToolManager 完成可重复验收，真实模型人工联调不冒充自动化证据。
