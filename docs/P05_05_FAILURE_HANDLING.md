# P05-05 故障处理

日期：2026-11-23。状态：已实现并通过专项测试和受影响模块回归；未进行真实模型或桌面交互验收。

## 模型请求策略

| 情况 | 当前行为 |
|---|---|
| 完全空文本且无工具请求 | 首次请求为空时补一次相同输入，再空则返回 `empty_model_response` |
| HTTP 429 / 5xx | 每轮最多三个请求；退避基准 1、2 秒，加 0～0.25 秒随机抖动 |
| 服务端 Retry-After | JSON 与 SSE 传输均解析秒数或 HTTP 日期；等待至少达到服务端提示，超过 Run 剩余时间则直接返回当前错误 |
| 认证、权限、非法请求、拒答、格式损坏 | 保留原错误，不自动重试 |
| 模型连接失败、超时 | 保守返回原错误，不推断上游是否已完成生成 |
| 已有文本或工具参数增量后失败 | 返回 `model_stream_interrupted`，关闭迭代器，不重放部分输出 |

重试只包围当前 `model_turn`，不会重新进入整个 AgentLoop，也不会重复执行前面已经完成的工具。退避用 `asyncio.sleep`，可被取消；请求与等待共享既有 Run 总期限。重试总上限是三个请求，不另行叠加空响应重试额度；重复请求不计为新的模型决策轮次。成功返回的空响应若携带已知 Usage，会累计进最终用量；供应商未返回的失败请求用量无法准确获知。

直接调用 Provider 或摘要模型接口没有新增自动重试；策略位于 AgentLoop，避免层层重试放大请求数。

## 重复工具保护

- 新增可信工具定义字段 `read_only`，默认 `False`。低风险或 `parallel_safe=True` 不等同于只读。现有 calculator/current_time 显式标为只读。
- 每个 Run 使用“工具名 + 键排序后的 JSON 参数”的 SHA-256 指纹记录尝试次数，不靠模型产生的 call ID 区分操作。
- 非只读工具的同参数调用最多尝试一次；只读工具同参数最多三次，以允许有限刷新。不同参数拥有不同指纹。
- 在调用 ToolManager 前登记尝试，因此超时、异常、权限拒绝等结果不会让模型通过更换 call ID 盲目重做同一写操作。此策略偏保守，可能拦住尚未实际执行的重复尝试。
- 重复调用仍生成对应新 call ID 的失败 ToolResult，说明本次未执行，并附带此前结果最多 512 字符的参考片段；保持 Assistant/Tool 配对。反复请求仍会受既有连续失败和最大轮数上限限制。
- 指纹仅存在于当前 Run 的内存中；新 Run、程序重启或不同参数不受此记录保护。当前没有事务性幂等键、外部副作用核对或崩溃后恰好执行一次保证。

## 连接断开策略

- 上游模型 SSE 迭代器在完成、失败或取消后显式关闭；接收到部分增量后发生错误不会自动重发整轮。未完整解析的工具参数不会进入 ToolManager。
- 下游桌面 SSE 断开时 Run 保持原有后台执行语义，HTTP 线程停止向断开的 socket 写入，不会创建新模型请求或再次执行工具。
- 后端为事件写入 `id: sequence + 1`，重连时读取 `Last-Event-ID` 作为下一条事件游标。未知 Run、非法游标、已过保留期的 Run 都有明确失败路径。
- 桌面保留原 EventSource 的浏览器自动重连，最多等待 30 秒；成功连接后继续原事件序列，失败超时后结束当前 UI 等待并尝试加载历史。恢复的是当前进程保留的事件，不是崩溃后恢复执行。
